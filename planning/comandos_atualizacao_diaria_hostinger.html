Atualização diária da base — Hostinger

Site: gerenciador-gclt.com · VPS: /opt/anexov · Serviço: anexov-api · Solução provisória via git (decisão de 2026-07-08)

Passo 1 Local (Windows) — commit e push dos CSVs

Depois da rodada diária, no repo do site (site_classificacao_beneficiarios_programa). Add cirúrgico: somente os 4 caminhos — nunca git add -A / git add ..

git add entrada/lpt/consolidado.csv entrada/lpt/consolidado_ucs.csv entrada/mla/consolidado.csv entrada/mla/consolidado_ucs.csv
git commit -m "base csv mla e lpt atualizada"
git pull --rebase --autostash
git push

Se não houve mudança nos arquivos, o commit falha com "nothing to commit" — tudo bem, nada a fazer.

Passo 2 VPS — pull como usuário deploy

Conecte no VPS (ssh) e rode:

sudo -u deploy git -C /opt/anexov pull --ff-only
⚠️ Git no /opt/anexov sempre com sudo -u deploy. Rodar como root planta arquivos root-owned em .git/ e quebra pulls futuros (FETCH_HEAD: Permission denied). Se acontecer, corrija com: chown -R deploy:deploy /opt/anexov

Sem restart: o backend recarrega os CSVs de entrada/ automaticamente quando o mtime muda.

Passo 3 Verificação

Confirme as datas dos arquivos e a saúde da API:

ls -la /opt/anexov/entrada/lpt /opt/anexov/entrada/mla
curl -s https://gerenciador-gclt.com/api/health
  • As datas dos 4 CSVs devem ser as de hoje.
  • O /api/health mostra as contagens da referência (chaves_uc, odi_ref) e a integridade (contratos com/sem referência) — os números devem refletir a base nova.

Só se necessário Casos especiais

Se base_contratos.json também mudou (ele NÃO recarrega sozinho — cache por processo):

systemctl restart anexov-api

E se a cópia do front (modelo/src/base_contratos.json) mudou, rebuild:

cd /opt/anexov/modelo
sudo -u deploy npm run build

Se o pull abortar com "local changes would be overwritten": algum arquivo rastreado foi alterado direto no VPS. Veja qual com sudo -u deploy git -C /opt/anexov status e resolva com cuidado (backup antes de qualquer git checkout --, que é irreversível).

🔒 Nunca versionar/commitar: backend/usuarios.json (usuários reais de produção — só existem no VPS), .env, backend/.env, senha e-mail hostinger. O repo GitHub deve permanecer privado.
